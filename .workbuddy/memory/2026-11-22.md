# 2026-11-22

## 真机部署接口（新增 scripts/a2_pi0/deploy/）

用户问：训练在本机、机械臂控制在另一台电脑，模型推理结果怎么真正跑到真机上。

调研两侧后确定方案：模型留本机做 TCP 推理服务，机械臂电脑（dora 图）加薄节点。

### 关键事实

- 机械臂侧是 dora-rs 图：`robot_real_pedestal.yaml` 里 `dora-openarm` 节点用
  `move_position` 输入收 8 维关节目标；leader 通过 `leader/follower_position_*` 提供。
  注入点就是这条位置流，不需要改驱动、CAN、使能逻辑。
- 已有 `arm_command_mux.py` 是"命令二选一"的先例，位置流需要一个同构的 mux。
- 四路相机在 `cameras/status_{global,chest,wrist_left,wrist_right}` 发布，
  且已做方向统一：global 与双腕 rot180-v1、chest identity-v1。**不能用 robot/camera_***。
- 训练侧动作语义：30 Hz、50 步、16 维 `[右 J1..J7, 右夹爪, 左 J1..J7, 左夹爪]` rad 绝对 IK 目标。
- 推理实测 275 ms（10 步采样）/255 ms（5 步），控制周期 33.3 ms → 必须分块异步。

### 落地内容

- `policy_server.py`：复用 real_training_support/real_four_camera_* 做预处理与 LoRA 加载，
  `--self-test`（预处理与训练逐元素一致）、`--probe`、`--serve`（stdlib socket + 长度前缀）。
- `policy_client_node.py`：observe/shadow/publish 三档，按绝对步号对齐的异步重规划
  （`--chunk-exec 20`），夹爪端点裁剪 + 单步跳变裁剪，帧龄与故障门限。
- `position_mux_node.py`：leader/policy 二选一，接近性联锁 0.05 rad、超时自动回落。
- `dump_inputs.py`、`dataflow_policy_patch.yaml`、`README.md`（联调 0–5 阶段与安全协议）。

### 已在本机验证

- 预处理与 `RealFourCameraDataset.__getitem__` 逐元素相等（4 个验证样本）。
- 端到端 259–261 ms，MAE 0.083 rad；prefix 模型前缀保持 1.2e-7 rad。
- loopback 客户端+服务端 25 s：20 步重规划、rtt≈250 ms、30 Hz 输出、零故障。
- mux 用假 dora 事件验证切换/联锁/arm_command 回落。

### 未验证 / 待现场确认

相机到训练相机名的映射、qpos 顺序、`move_position` 载荷类型（`--encoder`）、
执行频率 30 Hz 的实际跟踪效果。全部真机环节未做，需按 README 阶段 0–5 走。
