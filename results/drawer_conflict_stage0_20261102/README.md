# 冲突样本方案 · 阶段 0 可行性验证（未通过）

验证日期：2026-11-02。只读采集与离线专家运行，不训练、不改模型、不动评估起点。

原始数据：[stage0_grid.json](stage0_grid.json)（3 锚点 × 5 抽屉位置，含每组前 6 步的末端指令）。

## 结论

**按原设计（4 步动作窗口）构造冲突样本不成立。判定停止，不进入阶段 1。**

原因不是"专家不看视觉"——换成几何伺服专家后它确实看——而是**4 步动作窗口只有 0.133 秒，短到抽屉移动 ±40mm 造成的动作差异几乎为零**。

| 动作窗口 | 场景间专家末端位置差（中位 / 最大） |
| --- | ---: |
| **4 步（0.13 秒，当前模型）** | **0.00 / 0.01 mm** |
| 8 步（0.27 秒） | 0.14—0.26 / 0.41—0.53 mm |
| 16 步（0.53 秒） | 1.90—4.13 / 4.54—7.98 mm |
| 30 步（1.00 秒） | 9.25—20.33 / 23.18—39.06 mm |
| 60 步（2.00 秒） | 21.05—49.20 / 52.86—94.94 mm |

判据是"同一状态下不同位置的标签差异 ≥15mm 才算冲突成立"。4 步窗口下只有 0.01mm，差三个数量级。

## 过程

### 第一次尝试：关节空间专家 —— 差异恰好为 0

`drawer_feedback_oracle.FeedbackOracle.action()` 只读关节位置和速度：

```python
q = env.data.qpos[env.qpos_ids].copy(); v = env.data.qvel[env.velocity_ids]
distance = np.mean(((self.q - q[:8]) / self.scale) ** 2, axis=1)   # 匹配参考轨迹
goal = self.actions[min(progress + lookahead, len(self.actions) - 1)]
right[:7] += np.clip(.5 * (goal[:7] - q[:7]) - .03 * v[:7], -.08, .08)
```

它完全不读抽屉或把手的位置。实测：3 个锚点 × 抽屉移 ±40mm，专家末端指令差 **0.000 mm**。

这意味着历史上由它生成的 4192 条专家反馈查询，标签里同样不含场景位置信息。

### 第二次尝试：几何伺服专家 —— 看位置，但窗口内看不出来

换成 `contact_drawer_controller.ContactDrawerController`，它的 `open_drawer` 每一步都重读 `self._geom_pos("drawer_handle")` 并用数值 IK 求解接触位姿，是真正的几何闭环。

3 锚点 × 5 位置（Y = −40/−20/0/+20/+40mm）共 15 组，每组用 `collect_drawer_recovery.py --snapshot <同一状态> --episode-root <不同场景>` 生成恢复轨迹。

结果分两层，看起来矛盾但都是真的：

| 观察 | 数值 |
| --- | ---: |
| 整条轨迹的动作差异（295/297 帧不同，第 2 帧起） | **24—27 度** |
| 前 4 步（=模型的动作窗口）的末端指令差 | **0.00—0.01 mm** |
| 前 6 步的末端指令差 | 0.16—0.42 mm |

矛盾的解释就是 quintic 插值：控制器起步时加速度为 0，前几步手臂几乎没动。差异要累积到约 1 秒才变得显著。

## 这对已有结论的补充

之前的视觉依赖度探测（[drawer_vision_reliance_20261102](../drawer_vision_reliance_20261102/README.md)）发现：抽屉移动 40mm，020 的预测只变 1.0—1.3mm。现在有了另一半解释：

**不是模型"不愿意看图"，而是训练标签本身在这个时域上不含场景信息。** 即使把专家换成完美的几何伺服，4 步窗口内它的动作也和场景位置无关。模型学到"忽略视觉"是这份数据的**最优解**，不是缺陷。

## 修正后的方向

真正要改的是**标签的时间跨度**，不是数据量，也不是专家。

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| **A. 加长动作窗口**（推荐先验证） | 模型预测 16 步（0.53s），但部署仍每 4 步重观测（receding horizon），闭环频率不变 | 需改 `action_horizon` 并**重训**，不能微调——输出层维度变了。16 步时标签差异只有 1.9—4.1mm，可能仍偏小；30 步时 9—20mm，但预测越长越难 |
| B. 改标签定义 | 不预测"未来 N 步增量"，改预测"相对当前的对齐量/目标位姿" | 改动更大，等于重做动作表示，此前 015/016 的结论要重新验证 |
| C. 改观测几何 | 提高全局视角分辨率 | 会改变实验条件，已有 33/33、84/100、85/100 失去可比性 |

建议先做 **A 的最小验证**：把 `action_horizon` 从 4 提到 16（部署 chunk 仍为 4），训一个短课程，然后重跑 `probe_drawer_vision_reliance.py`：

- 视觉增益从 0.03 升到 0.3 以上 → 方向正确
- 仍在 0.03 → 说明 16 步还不够，直接测 30 步；若 30 步也不行，转方案 B

## 边界

- 只测了 1 个父起点（train 12）、3 个锚点、Y 方向 ±40mm。X 方向与高度未测。
- 15 组采集里 1 组失败：anchor2 / dy=+20mm 的夹持点 IK 位置误差 3.6mm，被专家拒绝。说明极端位置下几何约束会变紧，扩范围时要单独统计成功率。
- 末端位移用初始时刻的雅可比做线性近似，长时域（60 步）误差会累积，趋势可信、绝对值仅作量级参考。
- 本阶段没有训练任何模型，不构成模型改进或退步的证据，也不改变已封存的评估结论。
