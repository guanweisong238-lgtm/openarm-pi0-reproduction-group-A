# 鼠标人工示教

入口：`.venv/bin/python scripts/a2_pi0/teleop_drawer.py`。
打开独立XY控制面板和MuJoCo窗口，右臂固定初始夹爪朝向，左臂保持目标。
平面横向对应世界Y，平面向上对应世界X增大；Z滑条控制世界高度。
红点是请求目标。IK每步笛卡尔目标移动不超过2mm，关节分支变化限制0.08rad，
夹爪每控制步目标变化不超过0.005rad；不可达目标保持上一有效命令并在面板提示。
面板显示抽屉开度、双侧接触数量和法向力。

## 操作

- 鼠标拖动XY平面；Z滑条上下移动。
- O张开、C闭合，每次改变请求目标0.01rad，实际命令渐变。
- R开始一条新录制。已有未保存内容时拒绝覆盖；S保存并暂停。
- 空格暂停/继续物理仿真，暂停不记录重复帧。
- Home丢弃未保存内容并重置。Q或关闭窗口退出，未保存内容丢弃。
- 按保存后先等待数值回放检查完成，再在后台生成三路原始RGB和preview.mp4。
  录制帧率为仿真30Hz，墙钟速度受IK/GUI影响，不保证硬实时。

默认先实际执行原示教前75步，停在把手前方的预接近状态，方便练习抓握。
这部分不计为人工动作。R时保存完整物理初态，不回灌任何中间关节状态。
因此人工episode是warm-start任务条件；不能当作从ready出发的完整专家轨迹直接混用。
第一次建议先不开录制，练习XY/Z与O/C；熟悉后Home复位，再R开始。

## 产物和验收

保存在 `data/drawer_human/session_*/episode_*/`，不覆盖已有数据。
`episode.npz`先保存数值数据；`report.json`的`rgb_export_status`从pending变为complete后，
NPZ中包含三路RGB。后台日志为`rgb_export.log`，生成期间不要重命名或移动目录。
工具未把人工采集自动加入已有训练/验证清单；失败记录也保存，但不能标作成功训练示教。

记录执行前RGB/state与随后执行的16维绝对关节目标；RGB由数值轨迹在独立环境重放产生，
逐帧比对qpos并在1e-6误差门槛内才写入RGB。鼠标标记和控制面板不出现在模型图像中。
MuJoCo窗口直接施力被关闭，动作由IK目标产生。UI不自动绑定把手、不替人完成抓握。
成功指标为打开80mm保持1秒，再关闭到5mm内保持1秒，并检测双侧手指接触；
数值动作重放通过不等于人工操作成功，应再观看保存后的回放。

CPU自检：

```bash
.venv/bin/python scripts/a2_pi0/teleop_drawer.py --self-check
```

自检轨迹使用`selfcheck_`目录，不是人类示教，不进入训练集。

## 接触判定纠正

2026-10-24对人工episode_002复核：横杆双侧接触为0，但把手组件（横杆及两支柱）
双侧接触426帧，两侧均超过1N，最长连续4.27秒，拉动及推回期间均有双侧接触。
已结合打开/关闭保持和零误差回放，将该条修正为数值成功。
原始传感数组是横杆口径，不能改写其含义；组件接触由物理回放重算，见该条
`handle_component_audit.json` 和修正后的 `audit_report.json`。
旧拒绝记录保存为 `audit_report_bar_only_superseded.json`。

人工工具后续使用 `finger_handle_contacts(include_stems=True)`，面板和新记录均统计
整个把手组件，不计面板或腕部碰撞。report新增contact_scope。
脚本专家默认仍保留历史横杆口径以保证既有实验可比较。
正在运行的旧GUI及其RGB导出进程不会自动热更新；需重新启动GUI才能使用新统计。
RGB未生成完成前，数值成功不等于已具备可训练的完整图像数据。
