# 起步小样本拟合与后续验收

用户要求按顺序执行：最初动作拟合 → 短闭环 → 抓握/往返 → 验证起点/多种子。
前一道未通过时，不将后续阶段标记为通过；优先定位当前层的问题。

第一轮使用`fit_drawer_start.py`：

- 来源：`success13_early60_500_003/500`，两组各自从相同完整权重开始。
- train ID12仅0～8帧；每帧保留原未来16步动作，不截断为9步或修改原文件。
- validation ID3帧0/4/8只监控，无梯度。
- 完整train统计不重算，保留all32损失、图像增强、batch1、seed42。
- 200次更新，9帧平衡轮换，每帧22或23次；peak1e-5、warmup20、cosine到1e-6。
- 每50步固定检查9个train/3个validation观测，各用推理seed42/7/99。
- `lora`只更新原49,987,584个LoRA参数。
- `io`另外解冻state_proj、action_in_proj、action_out_proj共100,384参数，显式转FP32。
- 两组其他配置相同、优化器均重新初始化；视觉编码器继续冻结。
- 原生loss窗口每100步刷新并保存PNG/SVG。

事先定义的训练帧拟合门槛：三种子全部9帧首动作位置最坏误差<2mm，姿态最坏误差<2度。
这不是已验证的物理夹持容差或任务成功标准。还要单独检查保存后重载推理精度。

```bash
.venv/bin/python scripts/a2_pi0/fit_drawer_start.py --prepare-only
.venv/bin/python scripts/a2_pi0/fit_drawer_start.py \
  --tag start9_pair_001 --steps 200 --eval-every 50 --lr 1e-5
```

结果：`results/start9_pair_001/summary.json`；每个variant有独立RUN_DIRECTORY和检查点，
权重位于`checkpoints/pi0_openarm_drawer_start_fit_v001/`，不覆盖已有13条训练模型。

若拟合未通过，按前述诊断继续做接口、无关左状态、right8目标等小样本消融，
以门槛和逐帧改善趋势定位问题；不能仅凭200步失败断言模型容量不足。
如果启用`io_mask`，必须让推理端同样屏蔽归一化后的左8维；如果启用`io_mask_right8`，
还须由确定的控制器保持左侧目标。实时入口已按检查点协议恢复上述语义，并保留原始模型输出供审计。

即使小样本拟合通过，也只适合先检查训练覆盖的起步片段；尚不能据此要求它完成全任务。
后续需逐段扩展训练覆盖，保持原始13条数据的train/validation隔离，再验证完整往返。
