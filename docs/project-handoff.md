# 任务 C 交接

更新：2026-11-21。

任务、数据和待解决事项见[任务定义](task-real-cube-to-drawer.md)及[数据说明](../data/README.md)。22 条轨迹已按用户指示默认通过本轮探索性训练的人工审核；训练集 18 条、验证集 4 条。四路相机视觉缺陷仍存在。

已完成 1,000 步真实样本 LoRA 训练，使用训练集 1,000 个不同窗口，不足 1 epoch。固定 8 个验证样本的离线损失从 0.3704 至 0.1018；扩展 80 个验证样本上，500/1000 步分别为 0.1084/0.0949。见[训练报告](../results/real_pi0_four_camera_lora_001/README.md)。这些数字不是成功率；检查点为 LoRA 适配器，必须结合原 π0 底座及四路代码，且当前不支持续训。

独立进程重载检查中验证损失有小幅变化：清理前最近一次最大单样本差约 0.00164，超过原定 0.001 诊断阈值；成因未确认，详见训练记录。清理时任务 C 的共享支持代码已独立，真实数据加载检查及两步训练与同进程检查点恢复通过。

下一步：分析预测动作和数值重复性、扩展训练覆盖并进行独立场景评估；真机部署前单独制定执行器、控制频率、安全和停止协议。MuJoCo 回放仅为运动示意。

## 真机部署接口（2026-11-22 新增，未上机验证）

[scripts/a2_pi0/deploy/](../scripts/a2_pi0/deploy/README.md) 给出了把策略输出接到机械臂的
最小方案：模型留本机做 TCP 推理服务，机械臂电脑的 dora 图里加 `policy` 节点与
`position-mux`，`dora-openarm` 的 `move_position` 改由 mux 提供，人工与 VR 急停链路不变。
已在本机验证：推理侧预处理与训练 `__getitem__` 逐元素一致；单样本端到端 259–261 ms
（模型 243–245 ms）；loopback 下协议与 30 Hz 出点、20 步重规划节奏正常。
**未在 dora 运行时或真机上跑过**，相机映射、qpos 顺序、`move_position` 载荷类型、
执行频率仍需现场确认，联调须按该目录 README 的 0–5 阶段逐步进行。
